# 变更提案：source-lifecycle（源生命周期与观影体验补齐）

> 来源：参考项目 [LibreSpark/LibreTV](https://github.com/LibreSpark/LibreTV) 对照分析（见 `../architecture-refactor/benchmark.md`）。
> 定位：补齐**源管理生命周期**与**观影体验**两类能力；架构重构本身仍在 `../architecture-refactor/`。
> 依赖：`architecture-refactor`（接口层与领域模型分层）完成后实施；持久化相关部分依赖 `../local-first-storage/`。
> 配套：需求见 `specs/**`，设计见 [`design.md`](./design.md)。

---

## 1. 为什么

当前 LibreTV-TV 的源管理是"一次性快照 + 手工增删"：`assets/sources.json` 内置 30 个源，用户只能逐个添加/删除 URL。带来三个问题：

1. **源会失效，但用户只能手工一个个试**——采集站平均寿命短，失效是常态。
2. **换源/加源必须更新 APK**——对没有应用商店分发能力的自用项目尤其麻烦。
3. **观影体验缺少两个高频能力**——片头片尾跳过、播放失败自动换源。

参考项目在服务端聚合场景下已经把这些能力跑通（`subscription-sync.ts`、`skip-marks.ts`、`playback-recovery.ts`、`tvbox-parser.ts`），其**语义与边界可以直接借鉴**，但实现需重写为端侧形态。

## 2. 变更内容

### 2.1 远程订阅源（F1）

**用户故事**：作为用户，我希望填一个订阅 URL，应用定期拉取并同步源列表，这样不用更新 APK 就能换到可用的源。

**行为规范**

| 项 | 规则 |
|---|---|
| 订阅格式 | 兼容 LibreTV `SourceList` JSON v2（`sources[]` / `liveSources[]`，仅取 `sources`）与裸数组格式 |
| 刷新周期 | 关闭 / 1 天 / 3 天 / 7 天 / 14 天 / 30 天 |
| 调度 | 仅在应用处于前台时检查；单次最多刷新 5 个订阅；并发 2；后台刷新不阻塞首屏 |
| 失败处理 | 连续失败 3 次自动暂停该订阅；手动同步成功或修改周期后恢复失败计数 |
| 归属边界 | 订阅源以远端为准（手动编辑会被下次同步覆盖）；手动添加的源不受订阅影响；删除订阅时才删除其源 |
| 去重 | 按 URL 去重 |
| 上限 | 单个订阅最多导入 100 个点播源，超出截断 |

**验收**
- 添加订阅 URL 后可立即同步，源出现在源列表且标记来源为该订阅
- 远端删除某源后再次同步，本地随之移除
- 订阅 404/网络失败 3 次后状态变为"已暂停"，不再自动重试
- 修改刷新周期后失败计数清零

### 2.2 TVBOX / SourceList 格式导入（F4）

**用户故事**：作为用户，我希望直接导入社区里现成的 TVBOX 配置，把里面可用的 Apple CMS 接口收进来。

**边界（沿用参考实现的限制）**

- TVBOX `sites` 中符合 Apple CMS 特征的导入为点播源；`lives` 忽略。
- 跳过 Spider 引擎、XML 接口、不可直接调用的外链 JSON。
- 不支持 Base64 / 压缩包装的分享链接；不支持 TVBOX 多仓 `urls` 顶层结构。
- 导入前展示预览（可导入数量、被跳过的条目及原因），用户确认后执行。

**验收**
- 导入合法 TVBOX JSON 后正确列出可导入条目并可确认导入
- 含 Spider / 外链的条目被跳过且在预览中说明原因

### 2.3 导出与导入（F3）

**用户故事**：作为用户，我希望把源列表、设置、观看记录导出成一个文件，能备份或换机迁移。

**范围**

| 内容 | 导出 | 导入 |
|---|---|---|
| 源列表（含订阅配置） | ✅ | ✅（合并，按 URL 去重） |
| 应用设置 | ✅ | ✅ |
| 观看历史 | ✅ | ✅（可选，默认不覆盖） |
| 格式版本 | 带 `version` 字段，未来可迁移 | 兼容旧版本 |

**交互**：导出为 JSON 文件（系统分享）；导入通过文件选择器；导入前预览差异。

### 2.4 片头 / 片尾跳过标记（F2）

**用户故事**：作为用户，我希望在播放中标记片头结束、片尾开始，之后自动跳过。

**行为规范**

| 项 | 规则 |
|---|---|
| 标记类型 | 片头结束点、片尾起点、中段区间 |
| 交互 | 播放中按键标记 → 进度条着色显示区间 → 边界可微调、可试跳、可撤销 |
| 复用 | 按**归一化片名**为键，同影片后续剧集与同名资源自动继承标记 |
| 存储 | 本地持久化，随设置导出 |
| 与广告过滤的关系 | 现有 M3u8 广告过滤为"源侧自动"，本功能为"用户侧手动"；两者不冲突，同时存在时广告过滤优先 |

**验收**
- 标记片头结束后重播该集自动跳过
- 同名资源/下一集自动继承标记
- 撤销标记后恢复原状

### 2.5 播放失败自动换源 + 进度保持

> 架构细节（`PlaybackRecovery` 状态机、`PlayRequest.resumePositionMs`）已并入 `architecture-refactor` 的 `design-detail.md` §E.6 与 tasks 2.12/2.13；本变更仅负责**用户可见行为**与规格。

**验收**
- 当前源网络失败时自动尝试下一个可用源，用户无感继续观看
- 换源后停留在原剧集的相近进度位置（误差 ≤ 5%）
- 所有源均失败时提示"所有源均不可用"并提供"手动选源"入口

### 2.6 收藏记录（已移出本变更）

收藏记录的存储实体、主键规则（归一化片名唯一、来源可空）、收藏列表页与收藏入口，归入 [`../local-first-storage/`](../local-first-storage/) 的 `favorites` 能力（主键为归一化片名，与聚合层共用同一归一化函数）。

本变更只承担一项：**把收藏纳入备份包**（见 2.3）。

## 3. 不做（及理由）

| 项 | 理由 |
|---|---|
| 直播 / IPTV / XMLTV EPG | 与"点播聚合"定位不同，工作量与播放链路复杂度高，另开项目 |
| 鉴权 / SSRF 防护 / 反向代理 | 端侧直连无此风险 |
| PWA / 双主题 | 不适用于 TV 客户端 |
| "发布为链接"公开粘贴 | 公开外网暴露源列表，TV 端无收益且有安全风险；仅保留本地导出 |

---

## 4. 受影响规格

| 规格 | 变化 |
|---|---|
| `source-management` | 新增：订阅管理、第三方格式导入、源归属标记、导出与导入 |
| `playback` | 新增：跳过标记（片头片尾与中段区间）及其与广告过滤的优先级 |
| `settings` | 新增：备份导出与导入入口、跳过标记管理入口 |
| `content-discovery` | 不变（订阅源与手动源在聚合时等价） |
| `favorites` | 不在本变更修改；收藏由 `../local-first-storage/` 定义，本变更仅把收藏纳入备份包 |

---

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 订阅远端内容不可控（可能指向内网或非法源） | 仅接受 HTTP/HTTPS；拒绝回环/保留地址；端侧用户自担风险但在 UI 明示 |
| 订阅同步覆盖用户手工修改 | 源列表按"归属"分组展示，订阅源标记为"由订阅管理"，编辑时提示会被覆盖 |
| 自动换源导致用户不知情地换了内容源 | 顶部短暂提示"已切换到 <源名>"；提供"手动选源"入口 |
| 跳过标记误伤正常内容 | 标记默认不跨"归一化片名"复用；提供一键撤销与全局关闭 |
