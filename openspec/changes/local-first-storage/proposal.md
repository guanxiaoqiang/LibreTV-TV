# Proposal

## Why

当前应用的本地存储是「4 个 SharedPreferences + 1 张手工 SQLite 表」的拼装：`libretv_watch_history` 与 `libretv_search_history` 用 JSON 数组整表读写，`feed_cache` 只有 3 列且 `onUpgrade` 直接 `DROP TABLE`（加一列即清空全部缓存），源健康度与订阅状态无处安放。观影记录只能存 40 条、无法按影片聚合，收藏能力完全没有，云端请求缓存只有「首页卡片绘制子集」一种形态且只在用户访问过该标签后才存在。

结果是：详情页与选源页每次都要联网、搜索每次都要向全部采集源扇出、离线时除了历史几乎什么都打不开、任何结构演进都要靠整表覆盖来迁移。

本变更把持久化层统一为单一数据库，并把「本地先展示 + 后台刷新」确立为缓存与采集的通用范式，使端侧具备离线可用的内容目录能力。

## What Changes

- **BREAKING** 引入统一持久化层（Room + KSP），替换 4 个 SharedPreferences 文件与手工 `SQLiteOpenHelper`；播放地址仍不落盘
- **BREAKING** 缓存读取语义显式区分「新鲜 / 陈旧可刷新 / 已过期」三种结果，陈旧内容必须直接展示而不得先清空再填充（消除卡片闪屏）
- **BREAKING** 观影记录权威键改为「来源 + 影片 ID + 线路 + 剧集」，播放地址降级为当次快照；新增跨源归一化片名以支持同片多源聚合
- **新增** 收藏记录能力：以归一化片名为唯一键，收藏不强制绑定来源，提供收藏列表页与首页入口
- **新增** 内容目录：标题、别名、封面、来源清单、线路与集名落库，播放地址实时解析
- **新增** 后台增量采集：按优先级调度，与用户触发的请求完全隔离配额
- **修改** 搜索改为「本地索引优先 + 后台补采」，冷启动无索引时回退为原有扇出
- **修改** 详情页与选源页优先读取本地目录，缺失时联网补齐
- **新增** 缓存失效矩阵：签名型（来源集变化）、前缀型（来源级失效）、版本型（模型版本）三类机制
- **新增** 无损迁移：显式迁移取代破坏性迁移，现有本地数据在升级后完整保留
- **新增** 设置项：后台采集开关、采集配额、目录占用查看与清理

## Capabilities

### New Capabilities

- `local-storage`: 统一持久化层的存储契约——结构化数据与缓存载荷的落库边界、无损迁移与版本管理、缓存读取的三种结果语义、缓存失效与配额隔离
- `content-catalog`: 内容目录与后台采集契约——目录内容的构成与新鲜度、增量采集的优先级与配额、离线可用性、搜索的本地索引优先
- `favorites`: 收藏记录契约——收藏的粒度与唯一性、收藏列表的展示与删除、与观看历史的相互独立

### Modified Capabilities

- `watch-history`: 历史条目的权威键改为来源 + 影片 ID 维度、播放地址降级为快照、写入节流化、条数上限与跨源聚合
- `search`: 搜索改为本地索引优先、扇出降级为回退路径与后台补采来源
- `content-discovery`: 首页缓存读取语义明确化、陈旧内容的展示契约、后台静默替换不得造成卡片跳动
- `settings`: 新增收藏入口、后台采集开关与目录清理入口

## Impact

- **新增依赖**：`androidx.room:room-runtime` / `room-ktx` / `room-compiler`（KSP）、`androidx.work:work-runtime-ktx`（仅订阅同步等持久任务）
- **构建**：需启用 KSP 注解处理器，`minSdk 23` 满足 Room 2.6.x 要求
- **代码**：`data/local/**`（新增 Room 实体、DAO、迁移）、`domain/gateway/**`（新增纯接口定义）、`data/**` 现有 5 个 Store 逐一迁移、UI 层新增收藏页与目录新鲜度提示
- **数据**：现有 4 个 SharedPreferences 与 `feed_cache.db` 需一次性迁移，迁移过程不得丢数据
- **行为**：搜索结果来源语义、详情页打开速度、离线可用范围发生变化，需在规格中显式定义
- **依赖关系**：本变更依赖 `architecture-refactor` 提供的领域模型分层（`domain/gateway` 纯接口、`TitleGroup`/`SourceOffer` 契约）
